# Мини-CRM "Объекты и задачи"

React + TypeScript + Supabase.

## Запуск

```bash
npm install
```

Скопируйте `.env.example` в `.env` и вставьте Project URL и publishable key (Project Settings → API Keys). Ключ `service_role` в проект не кладётся.

В SQL Editor Supabase один раз выполните `supabase/schema.sql`.

Перед этим в Authentication создайте пользователей с Auto Confirm и выключите регистрацию новых:

- manager@test.com
- executor@test.com
- executor2@test.com

Пароль у тестовых учёток: `password123`.

```bash
npm run dev
```

## Как устроена система

В системе два вида сотрудников. Постановщик заводит объекты (стройки) и задачи, назначает исполнителя и принимает работу. Исполнитель видит только свои задачи: берёт их в работу и отправляет на проверку. Если работу не приняли, постановщик возвращает задачу на доработку и пишет, что исправить. Каждая смена статуса остаётся в истории: кто, когда, из какого статуса в какой и комментарий, если он был.

Кнопки на экране прячут лишние действия, но защиту делает база. После входа у сотрудника есть сессия. Любой запрос к данным идёт с этой сессией, и база сама оставляет только разрешённые строки. Исполнитель не прочитает чужие задачи, даже если откроет консоль браузера и попросит все записи: база вернёт только его. Поставить статус, которого нет в цепочке, тоже нельзя — база отклонит запрос. Вернуть задачу на доработку без комментария нельзя. Историю нельзя исправить или стереть отдельным запросом. Регистрации с сайта нет. Секретный ключ базы в сайт не входит. Ключ, который есть во фронтенде, только открывает дверь к API. Что отдать, решает база.

## Решения

- Vite нужен, чтобы собрать React и TypeScript. На правила доступа он не влияет.
- Роль лежит в `profiles`. В учётке Supabase отдельного поля "роль" нет.
- Статусы в базе: `new`, `in_progress`, `review`, `accepted`, `rework`. На экране они по-русски.
- Смена статуса — функция `change_task_status`. В той же операции база проверяет переход и пишет историю. Комментарий к доработке нельзя обойти вторым запросом.
- Исполнитель видит объект, только если на нём есть его задача.
- Исполнитель выбирается при создании задачи. Постановщик может сменить его позже.
- Сроки, файлы, чат и уведомления не делались: в задании их нет.
